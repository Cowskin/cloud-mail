# 2026-11-17 分组统计 D1 过载修复

## 证据与原因

北京时间 00:45 前最近一小时 D1 Insights：分组列表统计一次约 13,499.52 ms，
读取 205,083 行；分组成员统计四次平均约 3,539.44 ms。
生产 EXPLAIN 确认成员邮件关联使用 `idx_email_account_user_type_del_id`，
仅按 account_id 查找，is_del、unread 和 create_time 需要读取正文所在的数据页。
这是此前收件箱与搜索元数据优化之外的独立查询路径。

## 修复

- 新增 `idx_email_account_del_unread_time`，覆盖分组总数、未读数和最新时间；
  新增附件 account_id 索引，避免逐邮箱扫描附件表。
- 分组统计显式使用覆盖索引。成员列表通过 MATERIALIZED CTE 先完成过滤和分页，
  再关联本页邮件，避免统计 OFFSET 之前成员的邮件。
- 保持未读值 0、软删除过滤、空邮箱、所属用户、分组保护及回收恢复语义。
- 邮件正文仍在 D1；没有修改、删除或迁移原有邮件。两个索引须先于代码发布。
