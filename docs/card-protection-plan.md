## 核心设计

- D1 保留解析后的邮件原文和原卡号，便于关闭保护后恢复展示、忘记密码时人工恢复。
- 后端在返回邮件前生成保护后的展示副本；普通邮件响应不含原卡号或运行密钥。
  本地新增的单链接授权例外见下文：验密后只返回所选链接，地址可能携带原卡号或兑换凭证。
- 兼容隔壁 `CardCipher` 的 fixed-8/v2 算法：PBKDF2-SHA256 210,000 次派生、FF1
  加密中间 8 位、保留前后各 4 位并附短校验标签，输出 `JG_前4位_密文及标签_后4位`。
- 这是展示保护；数据库、备份和私有收信缓冲仍包含原文，继续受运维权限保护。
  当前正文仍在 D1；已有 R2 收信缓冲和备份流程不因本方案迁移或清理。

## 密码与设置

- 卡号保护密码独立于邮箱登录密码；首次开启输入新密码并确认。
- 密码规则与 apple_manage_tool 一致：非空、单行、最多 1024 个 UTF-8 字节，无 8 字符下限；保留大小写及首尾空格。
- 修改密码必须验证原保护密码；关闭功能也必须验证原保护密码，均由后端执行。
- 改密只更新运行密钥和配置版本；下次读取按新密码生成展示密文，不重写邮件正文。
- 不保存明文保护密码；运行密钥通过独立 Worker Secret 使用 AES-GCM 封装保存。
  D1 单例表为 `card_protection`，验密使用完整材料的随机盐 HMAC，不能使用卡号短标签。
  每 15 分钟最多 5 次密码操作尝试，成功后清零；D1 原子版本校验避免并发覆盖。
- 关闭时清除密封运行密钥；再次开启只需设置并确认新密码，不要求原密码，即使之前已配置过。
  再次开启会替换密码验证材料；修改密码和关闭功能仍须验证当前启用时设置的密码。
- 忘记密码时可由运维读取 D1 原卡号并受控重置；普通页面不提供免原密码关闭保护的入口。
- 由系统设置管理权限控制全站统一策略；所有用户及无所属用户邮件遵守同一保护状态。

## 读取与性能

- 不建立卡号检索表、不补录历史卡号索引，也不为此扫描历史正文。
- 展示时只处理本次需要读取的邮件，历史邮件可在正常读取时直接生成保护后的副本。
- 沿用现有列表携带正文的接口，按本次最多 50 封邮件转换展示副本；不另行改造阅读协议。
  密码派生只在密码设置或单链接授权时进行，日常读取不运行 PBKDF2。
- 每次请求从 D1 主键读取一条保护配置，仅按配置版本缓存解封后的加密上下文；不使用最终一致的 KV 缓存开关。
- 改密、开关变化后更新版本，前端清除旧阅读状态并刷新，不接受过期版本的邮件响应。
- 默认关闭时不解析或扫描邮件响应体；保护开启时同一批次的相同卡号只加密一次。
- 单字段超过 2 MiB 或单次超出 1000 个不同卡号时拒绝输出，不回退原文。

## 防止原卡号泄露

- 列表、摘要、详情、星标、新邮件轮询、开放 API、Telegram 查看和通知统一经过后端保护输出。
- 现有搜索结果也必须经过同一保护输出，不因暂缓卡号检索而直接返回原始正文。
- 同时处理 HTML、纯文本、标题及其他可能携带卡号的展示字段。
  识别 `X` 开头的 16 位字母数字卡号，支持大小写、空格/短横线分组和 HTML 跨节点拆分。
- 保留 HTML 排版结构、表格尺寸/对齐属性、class/id、受限内联 CSS 和响应式样式；
  使用 CSS AST 逐项过滤，移除外部字体、`url()`、`@import`、变量、内容生成、脚本及事件属性。
  HTML/body 样式使用包装节点承载，保留原邮件字体、间距及手机布局。
- 邮件链接按下节规则分级，受保护链接移除地址但保留按钮外观，点击后验证保护密码。
  图片仅放行已核对的 Apple 通用静态素材精确 URL，
  不允许查询参数、其他主机或其他路径，并设置不发送来源地址。其他图片、二维码、
  CID/data 图片继续隐藏，不尝试 OCR；附件列表、下载接口和发送附件仍停用。
- 开启时暂停原始 MIME 自动转发；Telegram 通知、查看及 AI 验证码提取均使用保护副本。
- 回复、手动转发引用及普通复制使用保护后的内容；前端不持久化原正文，处理已有缓存的失效与清理。
- 清理旧版 localStorage 阅读副本；本地草稿在展示、打开和保存时经过保护接口，不删除用户草稿。
- 邮件响应及 Telegram 页面使用 `no-store`；在途响应结束前核对配置版本。
  本页即时更新、同源其他标签通过版本事件刷新，其他在线客户端每 15 秒或窗口聚焦时复核。
- 保护开启但密钥或处理异常时返回占位或错误，不能回退为原文。日志不得包含原卡号、密码或正文。

## 已确定的边界

- 本期不新增卡号搜索或索引。保护开启时保留标题、发件人名称及地址筛选，方便查找订单号和人名；
  标题/名称查询使用既有元数据覆盖索引，不扫描邮件正文。搜索结果统一经过后端保护输出。
  不新增正文搜索；受保护的公开 API 仍拒绝正文查询。批量清理的保护限制保持原样。
- 普通标题/名称筛选沿用原字段的子串匹配；如果这些字段本身包含卡号，片段仍可能参与匹配，
  但返回结果不会显示原卡号。本方案不把普通搜索恢复视为专用卡号检索或命中推断防护。
- 这是受控展示保护，不是 D1 静态加密。数据库、备份、历史已下载文件与已发送的通知仍需运维权限保护。
- 已交付的页面、离线客户端、本地旧草稿原文件、浏览器既有缓存，以及外部对象存储的历史直链，不能远程撤回。
  不承诺识别其他格式或任意人为混淆的卡号；已核对通用装饰图之外的图片及附件采取隐藏策略，不宣称已加密其字节。
- 更新密码后，既有复制密文仍须用旧密码在兼容工具中解密；新读取使用新密码。
