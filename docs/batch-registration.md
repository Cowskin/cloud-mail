# 批量注册邮箱命名扩展

实现日期：2026-11-17（Asia/Shanghai）。00:53 已与邮件链接分级更新合并发布生产。

批量创建页沿用原有收件箱 / 独立账户、分组、查重、导出和批次记录流程，新增邮箱命名选项：

| 方式 | 示例（@ 前的部分） | 下一批 |
| --- | --- | --- |
| 顺序编号（默认） | `user001` | 编号按上一批数量递增 |
| 随机字符 | `user_k7m9x2qa` 或无固定前缀的 `k7m9x2qa` | 重新生成随机地址，不递增编号 |
| 编号 + 随机 | `user_001_k7m9` | 编号递增，随机部分重新生成 |

随机长度为 4–32，默认 8；支持小写字母和数字、小写字母、纯数字。
默认排除 `0`、`1`、`i`、`l`、`o`，可取消；固定前缀可留空。
分隔符仍支持无、短横线、下划线、点号。

## 生成和创建

- 格式示例为确定性的展示，不是实际待创建地址。点击“检测并预览”才使用
  `crypto.getRandomValues` 生成地址；拒绝采样避免字符取模偏差。
- 单批保持 1–500 个。批内地址去重并重抽，重试次数有上限；随机源异常或重复过多时
  提示重新检测。邮箱 @ 前不超过 64 字符，输入为空、非整数及不合法点号组合会拦截。
- 创建提交预览中的原地址，失败重试保留地址和请求 ID；服务端继续复检，不覆盖已有地址。
  已存在或已删除的地址按原策略停止整批或跳过；重新随机会替换整批预览。
- 参数修改会立即使预览失效；异步检测的旧结果不能恢复失效预览。检测和创建期间禁用规则编辑。
  创建后重新生成预览会先提示导出本次结果中的密码。
- 新命名参数写入既有 `rule_json`，历史记录显示对应规则；旧记录缺少 `addressMode` 时
  按顺序编号显示。无需新增 API、数据库迁移、绑定或 Secret。
