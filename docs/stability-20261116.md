# 2026-11-16 D1 过载与收信持久缓冲修复

## 故障证据

北京时间 13:34:02.508，生产版本 `966cbbd3-aa63-4e4d-896a-c9f1bc109159`
的 `/api/email/list`（聚合收件箱）和 `/api/account/list` 同时记录：

`D1_ERROR: D1 DB is overloaded. Too many resources consumed within a 10 second window.`

聚合总数统计最近一小时平均约 3,911 ms、读取约 198,335 行；六小时平均约
6,371 ms。原索引不含关联所需的 account_id，统计会回表访问邮件所在的数据页。
主题和名称包含搜索、分析页正文长度统计也存在正文大范围扫描。

## 实现

- 新增 `email_metadata`，只保存查询及统计所需的小型元数据与正文长度，主正文仍在
  `email`。三个数据库触发器同步新增、更新和删除，避免应用双写产生不一致。
- 聚合总数从覆盖索引统计；主题与名称搜索先扫描覆盖索引得到 email_id，再读取
  本页正文。用户过滤先解析 user_id。分析页和用户列表统计读取元数据。
- 相关只读接口在确认 D1 短暂错误后执行有限退避重试；索引缺失等结构错误不重试。
- 收信先把完整原始 MIME 保存到私有桶 `cloud-mail-incoming`，再写 D1。
  `MAIL_SPOOL` 与现有灾备桶、附件存储绑定分开，不迁移或删除历史正文。
- 每封新邮件预先投递延迟 120 秒的恢复任务。正常路径保留原来的即时处理和转发；
  D1/附件故障时保留原始对象，由 `cloud-mail-incoming` 队列补写。
  消费批量和并发均为 1，失败采用退避，最多 100 次后进入独立失败队列。
- `email_delivery` 与正文插入在 D1 同一事务内提交，附件元数据插入幂等。
  附件没有完成前不把邮件标记为完成。回执保留，重放不会复活用户已经删除的邮件。
- 每五分钟扫描一页旧的 pending 对象并重新入队，修复入队失败、运行时中断以及队列
  保留期耗尽的窗口。pending 对象不设自动过期，不因重试次数耗尽删除原始邮件。
- `/api/analysis/mailDelivery` 使用既有分析权限，返回待处理数量下界、是否还有更多
  以及本页最老对象年龄，不返回地址或正文。日志仅输出事件及计数。

## 数据库迁移与验证

在 `mail-worker` 运行同一套 Wrangler：

```sh
../d1-backup-worker/node_modules/.bin/wrangler d1 execute cloud-mail-db --remote --file migrations/20261116_mail_stability.sql
```

然后在项目根目录执行 `node scripts/backfill-email-metadata.mjs --remote`。
脚本分批补齐元数据，已有行安全跳过；单批超过 1 秒缩小下一批，超过 5 秒停止。
脚本失败时先检查缺口及原因，不重复运行未核对的写操作。触发器同步期间的新邮件。
发布前必须确认元数据全覆盖且无孤立行，并检查查询计划。

本地测试覆盖搜索/翻页/权限/保护分组、元数据同步、Unicode 长度统计，以及 D1
过载后恢复、持久存储失败、入队失败、事务已提交但响应中断、并发重放、附件失败、
拒收清理失败、队列退避和孤立对象重新入队。生产不会主动制造 D1 过载。

## 运维与边界

- 原 SMTP 调用中明确的黑名单、禁收及无收件人策略仍返回拒收；若故障导致延后处理，
  恢复任务会按策略记录拒收并清理临时对象，不能再修改已经结束的 SMTP 会话。
- 外部转发和 Telegram 当前均关闭。正常 SMTP 路径保留外部转发；恢复任务不能重建
  Email Routing 的原始 `message.forward()`，只能保证本地入库，记录转发不可用事件。
  Telegram/转发仍是辅助功能，不影响已经完成的本地收信。
- D1、R2、Queues 均有平台容量和可用性边界，不能承诺任何平台故障下零失败。
  R2 初始持久化失败必须抛出异常，不把仅在内存的邮件当成成功接收。
- 新增定时策略为 `*/5 * * * *`；保留原 `0 16 * * *` 每日维护。
- 回滚基线为上述旧版本；迁移为新增结构，代码回滚不会撤销它们。
  回滚旧代码会同时撤销新收信缓冲入口。已有 pending 对象、回执和队列必须保留，
  恢复兼容消费者后继续处理，不能清空队列或删除 pending 来“修复”故障。
